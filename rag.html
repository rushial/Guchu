① Document Ingestion

RAW DATA
Your document is the source of truth. A real RAG system first parses files such as PDFs, Word documents, webpages or databases into machine-readable text.

② Chunking

0 CHUNKS
Large documents are split into smaller pieces. The goal is to create chunks that contain enough meaning to answer questions without sending the entire document to the LLM.

Overlap: neighboring chunks share some text so important information isn't accidentally split apart.

③ Embeddings

VECTOR REPRESENTATION
Each chunk is converted by an embedding model into a numerical vector. This simulator uses a small educational vector representation rather than a real embedding model.

Real models may generate hundreds or thousands of dimensions.

④ Vector Database

STORAGE
The vectors are stored alongside the original text and metadata. A vector database lets us efficiently find vectors that are semantically similar to a query.

⑤ User Query

QUESTION
The user doesn't search for an exact paragraph. They ask a natural-language question. The system now needs to find the pieces of knowledge most relevant to that question.

⑥ Query → Embedding

VECTOR SEARCH
The question is passed through the same embedding model used for the documents. This produces a vector representing the meaning of the query.

⑦ Similarity Search

RETRIEVAL
The query vector is compared with stored chunk vectors. Higher similarity means the chunk is considered more semantically relevant.

⑧ Reranking

PRECISION
Many production RAG systems don't blindly send the first vector-search results to the LLM. A reranker can examine the query and candidate chunks more carefully and reorder them by relevance.
Why rerank? Vector search is fast but can sometimes retrieve chunks that are only approximately relevant. Reranking adds a second relevance check.

⑨ Context Construction

AUGMENTATION
This is the step people often miss when learning RAG. The retrieved chunks are inserted into a prompt that is sent to the LLM.

This is the "Augmented" part of Retrieval Augmented Generation.

⑩ LLM Generation

GENERATION
Finally, the LLM receives the user's question plus the retrieved context. It uses that context to generate an answer.
✨ AI GENERATED ANSWER
Key distinction: The vector database retrieves information. The LLM generates the response. The vector database itself does not "answer" the question.
